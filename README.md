# 拼豆图纸生成器（pindou）

把任意图片转换成 30×30 / 45×45 的拼豆（Perler / Midi bead）图纸，**全程本地运行，图片不上传任何服务器**。

## 快速开始

```bash
npm install
node gen.mjs --input D:/pics/cat.png --size 30 --palette midi
```

只想先看效果：

```bash
npm run demo      # 用内置测试图跑一遍，输出到 out/demo
```

## 如何运行

需要 Node.js 18 或更高（用到了内置 `fetch`）。全流程本地运行，图片不上传任何服务器。

### 1. 准备

```bash
cd D:/code/vibe/pindou
npm install
```

### 2. 选一种运行方式

**A. 图形界面（推荐）**

```bash
npm run gui
```

然后浏览器打开 **http://localhost:8765/**

界面操作流程：

1. **拖图**进页面（或点选文件）→ 立刻自动分析，原图上叠加显示 **蓝框 = 主体 bbox、橙框 = 当前裁剪区、绿框 = 双眼位置**
2. **点「裁到 8 / 10 / 12 格眼宽」**按钮，一键把眼部调整到合适大小
3. **选颜色**：「颜色」区点用色数量预设（`2 4 6 8 12 16 24 32 48 全部`），也可直接输数字；色卡下拉会显示真实色数（midi 73 / warm-nogreen 66 / warm-noncool 52）
4. 点**生成**
5. 出预览，下载 **A4 图纸**去打印

`http://localhost:8765/out/` 列出历史产物，方便翻查和直接打印。

> 端口被占用时换端口：`node serve.mjs out 8800`（第三个参数就是端口）。
> 改过 `gui/index.html` 或 `serve.mjs` 后请 `Ctrl+F5` 强制刷新，否则看到的是浏览器缓存里的旧界面。

**B. 命令行**

```bash
# 生成图纸
node gen.mjs -i input/cat_benben.jpg -s 45 --max-colors 16 --bg auto --out out/cat16

# 只看分析建议（主体 bbox / 眼宽 / 可直接粘贴的裁剪参数），不生成
npm run analyze -- input/cat_benben.jpg 45 debug

# 先用内置测试图试一遍
npm run demo      # 输出到 out/demo
```

GUI 和命令行**不是两套逻辑**——后端直接 spawn `gen.mjs`，所以改算法两边同时生效。

### 3. 自检

```bash
npm run test:gui     # 静态自检 + API 回归；API 测试自己起临时实例再关掉，不留后台进程
```

## 图形界面细节

- 页面会把**主体 bbox**（蓝框）、**当前裁剪区**（橙框）、**双眼位置**（绿框）直接叠在原图上；
- **用色数量**点预设即可（2/4/6/8/12/16/24/32/48/全部），也可直接输数字。注意上限不等于实际用色：`--max-colors` 是 k-means 的聚类中心数 K，图片本身没有那么多层颜色时空簇会被丢掉——同一张猫图实测上限 4/12/24/99 只用出 4/8/10/12 种，所以生成后会单独显示**实际用了多少种**（采购要按这个数算）；
- 色卡色数由 `/api/palettes` 从 `palettes/*.json` 现读，前端不写死，改色卡文件不会让界面显示过期数字；
- 自动算出「眼睛在当前裁剪下占几格」，并给出**一键裁到 8/10/12 格眼宽**的按钮——这是 `lib/analyze.mjs` 的核心用途；

## 输出文件（默认在 `out/`）

| 文件 | 用途 |
| --- | --- |
| `pattern-a4.html` | **A4 打印版**，浏览器打开后 Ctrl+P，含坐标、5/15 格分区线、色号图例 |
| `pattern.svg` | 矢量图纸，屏幕放大查看用 |
| `preview.png` | 纯色块预览，快速核对效果 |
| `chart.txt` | 数字图纸表格 + 图例 + 用量（记事本可直接打开） |
| `colors.csv` | 用量清单：色号 / 名称 / HEX / 颗数 / 建议采购量 |
| `pattern.json` | 规整的网格数据，想改图案或接其他程序时编辑它 |

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-i, --input` | 必填 | 图片路径（jpg / png / webp / bmp / tiff） |
| `-s, --size` | 30 | `30`、`45`，或 `宽x高`（如 `40x30`） |
| `-p, --palette` | midi | `midi` / `generic`（无品牌高饱和色卡）/ 自定义 JSON 或 CSV 路径 |
| `-n, --max-colors` | 24 | 用色上限，越少越好拼（12~18 最舒服） |
| `-m, --mode` | color | `color` 彩色填充；`mono` 黑白打印、格内标两位色号 |
| `--shape` | circle | `circle` 圆形豆；`square` 方块 |
| `--labels` | 关 | 彩色模式下也在格内写色号 |
| `--despeckle` | 1 | 0~3，清除孤立碎点，越大越干净 |
| `--min-count` | 0 | 例：`3`，把只有 1~2 颗的颜色并入最接近的颜色，省得单独买一包 |
| `--bg` | 关 | `auto` 压平背景：把背景里的花纹/渐变统一成纯色，主体更突出、更好拼 |
| `--bg-colors` | 3 | 背景有几种主色（1~3）。原图背景是「橙+白」两色就填 2 |
| `--bg-threshold` | 20 | 背景归并容差（Lab 距离）。调大→背景更干净但可能吃掉肤色等浅色主体 |
| `--bg-ring` | 2 | 从最外几环取样判断背景色（避开最外圈的深色描边） |
| `--bg-mode` | global | `global` 全图替换背景色；`flood` 只替换从画面边缘连通进来的背景（更保守） |

### 人物特写 / 去背景

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--crop x,y,w,h` | 无 | 按**原图像素**裁剪后再缩放。做人物特写必用，裁成方形可避免二次裁切 |
| `--sharpen` | 0 | 0~1.5 锐化。缩放会把睫毛/瞳孔插值成灰边，锐化能把边界拉回来，五官更清楚 |
| `--cell-mm` | 5 | 豆子直径。`5`=Midi 中豆（45 格≈22.5cm）；`2.6`=Mini 小豆（72 格≈18.7cm，同一张 A4 里分辨率更高、眼睛更大） |
| `--bg-cut N` | 关 | 在**原图分辨率**上抠掉背景（背景像素转透明 → 图纸上留空、不放豆）。N=背景主色个数。必须在缩放前做，缩放会抹掉勾边线导致分割失败 |
| `--bg-cut-th` | 26 | 抠图容差（Lab 距离）。调大删得多，但肤色/白衬衫这类和背景同色的区域也会被吃掉 |
| `--bg-cut-keep x,y,w,h` | 无 | 保护框（原图坐标），框内像素永不被删。水流仍能穿过框去删别处背景 —— 用来保护脸和衬衫 |
| `--bg-cut-depth` | 边长 34% | 背景水流最大深度。调小只删画面外围，主体更安全 |
| `--bg-cut-ring` | 14 | 背景色从原图最外几像素采样。太窄会只学到外框/描边色，导致分割失败 |
| `--bg-box x,y,w,h` | 无 | 手动指定人物包围盒，框外整片当背景（比按颜色自动分割可靠） |
| `--bg-fill` | 留空 | 配合 `--bg-box`：框外填指定颜色，如 `--bg-fill "#FFFFFF"`；不填则留空不放豆 |
| `--buffer` | 0 | 例 `0.1`，主体四周留 10% 白边 |
| `--brightness / --contrast / --saturation` | 0 / 0 / 1 | 调色，如 `--saturation 1.3 --contrast 0.1` |
| `-o, --out` | out | 输出目录 |
| `-t, --title` | 图片名 | 图纸标题 |
| `--no-legend` | 关 | 不生成图例 |
| `--override` | – | 校正色卡：`--override "A07:#111111;C01:#00FF00"` |
| `--list-palette` | – | 打印当前色卡全部色号后退出 |

## 照片还原：已有拼豆图纸 → 高清模板

手里的图若是**别人已经拼好的图纸照片**，用 `photo2grid.mjs` 逐格识别，直接得到可打印模板（色值取自照片底部材料清单，所以和原图纸一致）。

```bash
node photo2grid.mjs -i input/walnut.jpg --cols 49 --rows 59 \
  --codes "A10,A11,A15,D25,D6,F10,F11,F8,G13,G14,H1,H11,H18,H2,H20,H3,H7,H13" \
  --counts "48,38,5,39,52,63,84,40,16,1,4,1682,3,193,1,16,550,56" \
  --swatches "800,822,17;836,858,1" -o out/walnut
```

| 参数 | 说明 |
| --- | --- |
| `--cols / --rows` | 图纸的格数。照片上有坐标数字最好数出来；也可以把底部材料清单的颗数加总，再拆成 `列数 × 行数` |
| `--codes` | 色号，从左到右、从上到下，按材料清单的顺序 |
| `--counts` | 各色号颗数。**强约束**：识别完会自动把每色数量校正到与清单一致（改动格的颜色损失最小） |
| `--swatches` | 材料清单色块所在行 `"y0,y1,个数;y0,y1,个数"`（照片像素坐标），个数之和须等于色号数 |
| `--grid` | 手动指定网格 `"x0,y0,格宽,格高"`。不给就自动定位 |
| `--no-compare` | 不生成 `compare.png`（原图与还原结果并排对比，用来核对还原是否准确） |
| `--cell-mm` | 豆子直径，默认 5 |

自动定位网格的做法：先找纸面范围（排除手机黑边）→ 追踪网格线 → 最小二乘拟合 `位置 = 原点 + 周期 × k` → 用「交叉点增强信号」互相复核。照片有透视或拍摄角度不正时 rms 会变大，这时用 `--grid` 手动指定更稳。

输出与 `gen.mjs` 完全一致（`pattern-a4.html` / `pattern.svg` / `preview.png` / `chart.txt` / `colors.csv` / `pattern.json`），另加一张 `compare.png`。

## 打印

1. 用浏览器打开 `pattern-a4.html`；
2. 纸张 **A4**，缩放 **100%**（不要选"适应页面"），勾选 **背景图形**；
3. 先打印一页量一下实际格子边长：5mm 豆应为约 5mm，不准就调 `--mode` 之外的缩放（改 `lib/render.mjs` 里的 `PAGE_W`/格子计算）。

细线每 5 格一条、粗线每 15 格一条，长图纸不容易数错行。黑色激光打印建议 `--mode mono`，不费墨。

## 色卡校准

`palettes/midi.json` 是按 Midi 常见「字母+序号」体系整理的**近似**表，色值为标准 sRGB，不同批次实物会有偏差。三种校正方式：

```bash
# 1) 临时校正几个关键色
node gen.mjs -i pic.png --override "F01:#D02020;H01:#111111"

# 2) 直接改 palettes/midi.json 里的 hex（长期使用推荐）

# 3) 用自己的色卡建表：mycard.csv，列顺序随意，支持 HEX 或 R,G,B
#    色号,名称,HEX
#    A07,芥末黄,#C9A227
#    H01,黑,17,17,17
node gen.mjs -i pic.png --palette mycard.csv
```

没有色卡时用 `--palette generic`（程序生成的高饱和通用色表），或直接把 `palettes/midi.json` 里的 hex 换成你手上豆子的实物色。

## 尺寸与拼板

- 5mm 豆：30×30 ≈ 15×15cm，45×45 ≈ 22.5×22.5cm。
- 单块 29×29 拼板放不下 30×30，需要两块拼接；45×45 建议直接买 57×57 一体板。
- 拼接缝尽量落在图案边缘，第一步先在纸上轻点标记中心再向外拼。

## 出图前先量一遍

裁剪框靠目测常常差一倍以上（目测 24px、实测 11px），定完再出图才发现糊就晚了。
`node test/analyze.mjs <图片> [格数] [debug]` 一次跑完：

```bash
node test/analyze.mjs input/cat_benben.jpg 45
```

- **主体 bbox**：四角采样定背景色，扫出非背景像素外接框，直接给出可粘贴的 `--crop x,y,w,h`；
- **眼部测量**：局部自适应阈值切暗块（固定阈值会漏掉偏亮的虹膜），按「成对 + 被亮色包围 + 尺寸先验」挑出双眼，输出眼宽、眼线位置、双眼包围盒；
- **清晰度换算**：把「原图眼宽多少像素」换算成「目标格数下眼睛几格宽」，并反推达到 8/10/12 格需要裁到多宽；
- **构图建议**：cover 会裁掉多少、contain 会浪费多少颗；
- **色相过滤**：按色相区间剔除色卡里的色号，解决暖色主体暗部被吸成墨绿/藏青的脏色块。

`debug` 参数会打印过筛暗块的坐标，用来核对「哪块才是眼睛」。

眼部检测会带一个置信度：**这张工具是为「人像 / 动物正脸」设计的**。核桃这类纯物体图总有两块深色接缝能凑成「成对、纵向对齐、间距合理」，收紧阈值只会让它换一对继续冒充。此时靠候选暗块总数区分——脸是「大面积亮 + 少数集中的暗结构」，核桃是「整幅都是深浅纹理」（实测核桃 71 个 vs 三个真实样本 8/16/29 个），超限即报 `low` 并说明原因。眼宽数值照常输出，但请别当眼部特写用。

量完直接出图：

```bash
node gen.mjs -i input/cat_benben.jpg -s 45x45 --crop 313,137,186,186 -n 12 -t cat --out out/cat-eye
```
